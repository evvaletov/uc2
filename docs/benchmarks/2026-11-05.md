# Collection benchmarks, 2026-11-05

All 60 create/restore trials recovered every file with the expected SHA-256.
UC2 stream deduplication reduced the size relative to its ordinary file writer
on the related-version collections, but 7z and tar+zstd produced smaller
archives on all five collections. These results do not justify expanding
snapshot/version-bundle architecture yet. The immediate follow-up is to profile
UC2's compressor and chunk-directory overhead, then test real legacy collections.

## Method

`scripts/benchmark_collections.py` generates five deterministic synthetic
collections with eight files apiece, roughly 4 MiB per collection. They model
small edits to binaries, reordered assets, edited source text, block-oriented
simulation checkpoints, and unrelated random data as a negative control.
These are workload models, not measurements of actual games or scientific runs.
The seed is 20261105; files have fixed timestamps. SHA-256 manifests accompany
the results.

Each method ran three times on the same Linux x86-64 machine. The tables use
medians. Archive sizes include all stored metadata and dictionaries. UC2-files
uses level 4; tar-UC2 uses the default ingest method; 7-Zip 26.04 uses `-mx=5
-mmt=1`; Zstandard 1.5.5 uses `-3 -T1`. Every method is single-process and
single-threaded for compression. The JSON records the platform and UC2 binary
hash. This is a small, warm-cache experiment on a shared host, so timings are
indicative and are not throughput guarantees.

GNU time supplies peak resident memory for each process. Wall time uses a
monotonic clock and includes process launch and the timeout wrapper. Tar
creation and unpacking are excluded from the tar-based timing/RSS measurements;
ordinary UC2/7z restoration includes writing the individual files. Thus restore
times describe different output steps and are not end-to-end backup comparisons.
Both tar codecs also pass an exact tar-byte comparison before file verification.

The new ingest path uses about 1.8-2.1 MiB peak RSS in these trials. The earlier
whole-input implementation measured about 6 MiB on the same 4 MiB fixture scale
in a single preliminary run. A separate regression check ingested 64 MiB under
a 48 MiB address-space limit and verified the restored SHA-256. This proves
that the payload no longer has to fit in RAM; it does not establish constant
memory. The indexes and central directory still grow with chunk count.
Unique raw chunks use a temporary spool, while completed output is staged beside
the destination. Budget disk space for both. An interrupted writer preserves
an existing destination but can leave its staged file behind.

UC2 ingest was faster than the chosen 7z setting and slower than zstd in these
trials. Its storage costs remained worse than both. The strongest size reduction
relative to ordinary UC2 was on source versions, but that was also where modern
codecs had the largest advantage. The random-data control confirms that the
deduplication index cannot create savings when content does not repeat.

No restic/borg comparison was run, and no repository-backup efficiency claim is
made. The existing ingest format preserves stream bytes as `part-N` occurrences;
it has no named snapshots, tar-entry preservation, or cross-archive sharing.

## Reproduce

Requires Linux, Python 3.11+, GNU time/timeout, 7zz/7z/7za, and zstd.
Allow at least 1 GiB of free space for fixtures and trial outputs.

```sh
cmake -B build-bench -DCMAKE_BUILD_TYPE=Release -DUC2_BUILD_TESTS=OFF
cmake --build build-bench
python3 scripts/benchmark_collections.py --uc2 build-bench/cli/uc2 \
  --output /tmp/uc2-collection-benchmark --repeat 3
```

The output directory must be new. Raw [JSON](2026-11-05.json) and
[CSV](2026-11-05.csv) retain all trials. Recreating the same corpus and settings
should reproduce sizes; timing and memory depend on the host.
