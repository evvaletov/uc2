# Alpha9 browser export and Total Commander routing

Published November 7, 2026 from `19c725a7a1142c17d727c6343986965fac060326`.

- [Python package](https://pypi.org/project/uc2/3.0.0a9/)
- [CLI, integrations, browser bundle and source](https://github.com/evvaletov/uc2/releases/tag/v3.0.0-alpha.9)
- [Live reader](https://evvaletov.github.io/uc2/reader/)

Alpha9 adds selected browser ZIP exports and offline use, and fixes native
32-bit Total Commander routing through ordinary `.uc2` plugin registration.
Review uses independent Kimi/Gemini/Grok attempts, with Kimi replacing Claude
at the user's request. This scope does not complete project-wide audit c9edf0b.
Release links and final validation are maintained in
[this page on main](https://github.com/evvaletov/uc2/blob/main/docs/releases/3.0.0a9-qa.md).

The browser exports up to 1,000 file versions and 128 MiB per ZIP, including
its inventory and headers. Every payload passes the UC2 checksum and receives
a SHA-256 digest. Portable numbered output paths map to original paths and
versions in `inventory.json`; empty directories are not exported. Any failed
file, cancellation or timeout prevents a partial ZIP download.

Offline saving caches only the digest-checked application, sample and notices.
User archives and decoded content are not cached. Updates wait for old tabs
to close. Browser storage may be evicted; the save action repairs missing
assets while connected. A native install prompt depends on the browser/OS;
OS-specific installation is not part of automated coverage.

Native Total Commander 11.58.1 tests use SHA-pinned, Authenticode-checked
executables on isolated Windows runners. Both architectures use `.uc2`,
normal WCX registration and no forced internal association. Exact extracted
file bytes and the loaded plugin are checked. Earlier users should remove
`*.uc2` / `**u2r` internal associations as described in the plugin README.

## Validation scope

`web/test_browser.py` runs in Chromium, Firefox and WebKit. It compares original
Huffman/Turbo and modern rANS downloads against the native Python reader;
checks selected/newest/older versions, unsafe and truncated names, ZIP CRC32,
metadata and SHA-256; and exercises a 64 MiB successful download, per-file and
aggregate output limits, the 1,000-file limit, corruption, cancel and timeout.
The offline checks cover a failed initial install and retry, offline decoding
and ZIP export, cache contents, active/waiting cache repair, inconsistent
updates, old-tab isolation and activation after tabs close. Mobile layouts use
three widths and fonts. Only same-origin static GETs and local Blob reads are
allowed. WebKit's expected errors from deliberately corrupted responses are
matched narrowly during that test; other page errors fail the suite.

## Review repairs

The first Gemini review found that truncating a long ZIP leaf after trimming
dots could create a Windows-incompatible trailing dot. Truncation now precedes
trimming; a long-name fixture verifies it. Initial offline installation also
waits explicitly for its worker state and reports failed downloads before retry.
Maintainer review added digest verification to cache-miss network reads and
readiness/repair checks for waiting updates, preventing mixed builds after
partial cache eviction.

The documented 30-second inactivity cutoff remains deliberate, including on
slow devices. Raw original paths are inventory metadata; only numbered portable
paths become ZIP destinations. Per-response Cache writes are atomic, and
verified responses from different builds live in separate cache names.
Large-download tests exercise the existing Blob URL lifecycle; requests started
before revocation retain their resource under the
[File API model](https://w3c.github.io/FileAPI/#dfn-revokeObjectURL).

## Follow-up review

Gemini and Kimi completed three review rounds. Round 1 produced the repairs
above. Rounds 2 and 3 had no confirmed new blocking or substantive issue after
checking findings against the native API and documented contract. Round 3
Gemini returned no findings. Kimi's remaining suggestions concerned redundant
ZIP preflight checks, reporting failed updates while the current offline shell
remains valid, and earlier selection-limit hints; none permits unsafe output
or a false verification result. The ZIP builder also enforces its limit for
every added entry, including the final inventory.

The native name buffer is 300 bytes, so oversized-leaf scenarios in review
cannot reach JavaScript. Hosted HTTPS/localhost and current tested engines are
the supported setup. Reporting the complete current-version cache after a
failed newer update is valid; page/cache version mismatches are shown explicitly.
Raw prompts, outputs, statuses and detailed triage are retained locally in
`.git/qa-alpha9-20261107/`.

Grok returned no verdict before its 600-second timeout in all three rounds.
Those attempts are not approvals. Completed independent coverage is Gemini
plus Kimi, with no Claude calls; the full project audit remains open.
