# Alpha12 audit repairs and collection scaling

Alpha12 includes the [13 November project audit repairs](../qa/project-2026-11-13.md):
decoder and directory-parser error handling, allocation and storage failures,
Windows file operations, CLI selection and staged-output cleanup, tar directory
metadata, and snapshot input validation. Writer and WCX metadata indexes avoid
repeated scans on large archives. The optional libarchive proposal uses seekable
input; its upstream acceptance remains pending in
[PR #3832](https://github.com/libarchive/libarchive/pull/3832).

The native CLI now indexes parent directories and filename groups while reading
the archive directory. It computes stored-version numbers once after reading,
preserving listing order, version selection and first-parent-ID behaviour.
The new regression test covers repeated names, duplicate directory IDs, mixed
file/directory names, CP850 names, missing parents and 100,000 files.

The [scale and recovery record](../benchmarks/2026-11-14-scale-recovery.md)
contains the measured CLI results, multi-GiB snapshot workload, tests at the
default limits and recovery tests. The snapshot format and fixed limits are
unchanged. Tests use process termination and a private full filesystem; they
do not establish power-loss durability. The [snapshot guide](../snapshots.md)
describes manual lock recovery and abandoned restore staging.

Release artifacts include twenty CPython 3.10–3.14 wheels for Linux x86-64,
Windows x86-64 and both macOS architectures, four standalone CLI packages,
source, the browser reader, WCX, MC and libarchive review bundles. Standalone
CLI downloads do not include Python snapshot commands. WCX and MC packaging
does not mean their catalogue or upstream proposals have been submitted.

`BUILD-INFO.json` in the release identifies the source commit and its four CI
runs. `SHA256SUMS` covers the other release assets. The SDF repository mirrors
the source and release tags; GitHub hosts the downloadable binary bundles and
PyPI hosts the Python distributions.
