# Alpha11 named-file chunk sharing and libarchive submission

Alpha11 adds optional shared payload chunks across named files and stored
versions, including tar-entry and opaque-stream ingestion. Use `--chunked` or
`UC2Writer(..., chunked=True)`. The default writer remains compatible with the
existing format. Method-11 archives require a11 or newer full readers; the
optional LGPL libuc2read dependency deliberately rejects them.

Local checks cover 215 Python tests, 29 native CTests including DOSBox-X,
all compression levels, partial edits, versions, empty files, hostile references,
changed payloads, compressed word boundaries and staged extraction failure.
Native regressions cover invalid central-directory recipe lengths, rANS symbol
and end-marker validation, and the 64 MiB decoded-directory limit. Four thousand
versions with repeated long names now round-trip; a ratio heuristic previously
rejected these valid archives in both writer modes.

The browser/WASM reader, WCX fixture driver and full libarchive adapter include
chunked-archive cases. Actual bsdtar reads named chunked files through paths and
pipes, and restores a separate 128 MiB legacy entry under a 96 MiB address-space
limit. Sanitizer runs exercise archive extraction, chunk recipes and codec
round-trips. The [benchmark](../benchmarks/2026-11-07-chunk-sharing.md) reports
both reuse gains and the 9.1% size regression on an edited public-source corpus.

The submitted [libarchive PR #3832](https://github.com/libarchive/libarchive/pull/3832)
is a BSD adapter using the separate optional
LGPL legacy reader, disabled by default. Current-master validation passes all
969 libarchive tests, plus focused enabled/disabled CMake and enabled Autotools
checks. A format-registration capacity bug was fixed after full-suite testing
exposed it. Upstream acceptance of the dependency and format ID remains external.
The [submission record](../../contrib/libarchive/upstream/REVIEW.md) tracks it.

Independent scoped reviews use Kimi in place of Claude, Gemini, and opportunistic
Grok. Failed or empty reviewer calls do not count as clean reviews. The broader
project-wide audit remains open. TC and MC proposals remain unsent.

Publication, exact-commit CI and installed/public artifact verification are
recorded here after release.
