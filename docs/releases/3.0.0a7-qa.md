# Alpha7 browser reader and preservation toolkit

The two features requested on November 7, 2026 are implemented. Release
publication and final CI results are recorded below as they complete.

## Scope and behavior

The browser reader compiles the existing C decoder with Emscripten 4.0.15.
A worker reads local File/Blob data through WORKERFS. Users can inspect paths,
stored versions and raw metadata, verify UC2 checksums, download verified files,
and save an inventory. Input is capped at 256 MiB, entries at 10,000, decoder
allocation at 64 MiB, each decoded file at 64 MiB, and verification at 1 GiB.
WebAssembly memory is capped at 256 MiB. The UI terminates the worker after
30 seconds without progress or five minutes overall. Partial completed checks
survive a timeout; further decoding requires reopening the archive.

`uc2-preserve` inventories file/directory inputs and creates verified ZIP/tar
exports. Manifests preserve every version, original path, raw DOS timestamp,
attributes, compression method and decoded SHA-256. Numbered export paths
avoid collisions. Original archives are opened read-only. A failed source or
entry is recorded; destination errors abort the staged batch. An existing
destination is refused, including a directory created by another caller before
publication. Output parents must be controlled by the caller.

Neither feature claims support for Turbo/method 80 or multi-volume archives.
Arbitrary tags, original compressed streams and master blocks remain in the
source archive. ZIP/tar conversion does not replace preservation of originals.

## Validation

- 110 installed-package Python tests pass locally, including versions,
  metadata, ZIP/tar byte comparisons, checksum failures, each resource limit,
  symlink input, named pipes, output failures, source mutation and publication
  races. Existing reader/writer/mount tests remain included.
- Compiled-reader tests pass in Chromium 156.0.8078.4 and the older cached
  browser. They cover all five original-encoder fixtures, modern rANS,
  stored versions, exact downloads and SHA-256, inventory, unsafe/reserved
  filenames, malformed archives, cancellation, timeout recovery and no uploads.
  Narrow layouts are checked at 320, 390 and 800 pixels with three font choices.
- Sphinx builds with warnings treated as errors.
- Three historical archives (BLKTXT, MKMSG and UC2INFO) migrate successfully
  to ZIP and tar. All 88 decoded file sizes and SHA-256 hashes agree with the
  independent Go decoder at commit `53622f89ada1cf0d4a69f91b653bdd44ec5b0f92`.
  Their URLs, source hashes and expected metadata are pinned in
  `tests/archives/historical.json`. Third-party payloads are fetched separately.

The initial Docs CI run found a narrow-screen overflow caused by differing
font metrics. The action buttons now wrap and grid tracks can shrink; expanded
font/viewport tests cover that regression. The first candidate's native builds,
fuzzing and integration-package checks passed. Final candidate results follow.

## Independent review

This is a scoped review of the two new features, authored by Codex. Kimi
replaces Claude at the user's request. No restricted reference material was
involved. It does not close the separate full-project audit, c9edf0b.

Round 1: Gemini and Kimi completed. Their findings led to worker timeout-state
repair, incremental verification results, per-entry preservation limits,
separation of source and destination failures, consistent symlink handling,
and exclusive reservation of new output directories. The fixed 64 MiB browser
file limit is an intentional documented resource bound. Grok timed out after
600 seconds without a review; that attempt is not approval.

Round 2: Gemini and Kimi completed. Further fixes cover destination read and
container-validation errors, unreadable directory traversal and invalidating
decoded hashes when the source changes. Containers close before cleanup.
Dot components remain visible as original metadata: browser downloads use safe
leaf names and never reconstruct archive paths on the user's filesystem.
Remaining review rounds and publication checks are pending.
