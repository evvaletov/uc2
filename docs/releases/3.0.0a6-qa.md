## Project audit

The audit started from `d7eb30e`, the alpha5 release plus status updates. An
immutable snapshot was used for independent review requests. No restricted
reference material was involved.

Local findings repaired before the writer work:

- BLAKE3 applied CHUNK_START to later blocks, finalized chunks after discarding
  their terminal block, and hashed a chaining value instead of the root parent
  block. All 35 official unkeyed vectors now pass, including incremental updates
  around block/chunk boundaries and finalization followed by further updates.
  The vectors are pinned in `tests/data/blake3-vectors.h`.
- LZ4 omitted the required terminal literals. The encoder now follows the block
  ending rules. Cross-checks against system liblz4 passed 306 combinations in
  both directions, including empty, short, random, repetitive, and 1 MB inputs.
  Length checks avoid overflowing pointer arithmetic.
- Delta decoding accepted missing END markers and output shorter than the
  declared length. It now requires an exact completed stream. Encoding checks
  allocation failures and rejects unrepresentable lengths; bounds checks use
  subtraction to avoid 32-bit overflow.
- CDC documentation misstated its update rule and its example omitted the last
  chunk. Exhausted scans now return a zero length; length arithmetic is bounded
  by the actual input.
- Maintained documentation had stale attribution, compression, integration,
  timestamp, and module-integration claims. The blog draft was rewritten around
  implemented behavior and measured results. Commands and license texts remain
  intact. The final prose-pattern scan found no em/en-dash clauses, spaced double
  dashes, or scanned stock phrases in maintained reader documentation.

The old CLI creator also narrowed file sizes, ignored read/write failures,
followed directory symlinks, and opened its destination with truncation before
compression completed. The writer API work below addresses that path.

## Writer API

Archive assembly now lives in `uc2_writer.c`, with the same interface used by
the CLI and Python's `UC2Writer`. File data is consumed into a temporary spool,
CDC grouping uses a sorted index, and custom dictionaries remain capped at
64,000 bytes. The CLI's whole-file allocation and global creator metadata are
removed. Each input, callback, path length, encoded name, format size, flush,
and final close is checked. CLI/Python output replaces the destination only
after successful assembly and close.

The C API accepts directory IDs and UTF-8 name components. Python adds recursive
filesystem input, bytes, and non-seekable binary streams. Limits and transaction
semantics are documented in the public header and Python guide. New core code
retains GPL-3.0-or-later; independent integration glue uses the user's approved
GPL/BSD choice. No third-party code was relicensed.

The new C writer test covers all eight levels, original-reader round trips,
versions, directories, CP850 names, short reads, empty archives, callback errors,
format limits, invalid names/parents, and state transitions. Here "original
reader" means the existing portable decoder; the separate DOSBox test covers
the original DOS application. The installed Python wheel passes 75 tests on
Linux, including writer atomicity, abort, stream errors, reentrancy and symlinks.

All 25 regular CTests now pass; the C writer regression also passes ASan/UBSan.
The initial C test incorrectly required uc2_extract to return exactly zero;
its documented nonnegative success result was corrected in the assertion.
The DOSBox test passes in both directions against UC2 Pro (8.55 seconds with
headless SDL). A 64 MiB file archive is created under a 48 MiB address-space
limit and restores byte-for-byte. The two pinned source collections produce
the same archive sizes as alpha5: 95,817 and 355,021 bytes, with verified restores.
These single-run checks establish unchanged sizes, not a new speed claim.

Source-comment review also corrected the legacy ingestion module's stale CLI
version description and invalid cp/rsync pipe examples. Descriptive punctuation
in owned comments was simplified; original third-party copyright/license text
was preserved. The Linux CI lint initially rejected calls inside assertions in
new regression tests. Calls now evaluate outside assertions, and the lint passes.

The Python extension was also rebuilt with Clang 21 ASan/UBSan. All 75 tests
passed with the matching shared ASan runtime preloaded and UBSan set to halt
on errors. Leak detection was disabled for this Python-hosted run.

The final prose scan covered 18 maintained reader-facing documents and 9,976
words. It found zero matches for the scanned em/en dashes, curly quotes, spaced
double dashes, stock stems, or assistant-language leakage. The README contains
948 words and the Python guide 1,164. Historical audit/benchmark reports,
internal planning, and generated upstream review material were outside this
reader-document scan. Owned source comments received a separate review.
