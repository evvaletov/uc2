# Alpha13: layout selection and transactional CLI output

`--chunked=auto` builds the classic and shared-chunk layouts from the same
captured inputs and keeps the smaller complete archive, choosing classic on
ties. Python accepts `UC2Writer(..., chunked="auto")`; C accepts
`UC2_WRITER_AUTO_CHUNKED`. The default and explicit chunked formats are unchanged.
Both candidates must fit the existing limits. Auto costs both compression
passes and temporary space for both archives; any assembly failure aborts
before output. Statistics describe the selected archive.

On the original public-source benchmark, auto emits 378,945 bytes instead of
413,429 bytes with explicit chunks. It retains the edited-binary result of
1,556,525 bytes versus 3,763,693 bytes in classic mode. All three trials per
collection restored every file exactly. The [measurement record](../benchmarks/2026-11-20-auto-chunks.md)
includes the other four collections, inputs, timings and limitations.

CLI extraction stages and verifies each file, closes it successfully, then
publishes it. Existing files survive decoding, write, close and publication
errors. Without `-f`, files already present are skipped; a newly appearing
output is preserved and publication fails. OTS attachment hashes the archive
prefix as it copies it into a staged replacement. Proof extraction also stages
its output. Windows temporary-file cleanup and metadata updates now accept
the same long paths as file creation. The Windows entry point converts Unicode
arguments to UTF-8 before parsing.

These are per-file operations. Earlier extracted files remain committed if a
later file fails. The caller must control the destination tree and keep source
archives stable. Abrupt termination can leave a temporary file; power-loss
durability is not guaranteed. OTS attachment retains the nine POSIX `rwx` bits
or Windows read-only attribute, but not special mode bits, ownership, ACLs,
extended attributes or hard-link relationships.

DOS refuses existing output targets, including OTS attachment. DJGPP's
[`rename` deletes an existing target before moving the new file](https://delorie.com/djgpp/doc/pitfalls.html),
so it cannot provide the required replacement guarantee. Use fresh extraction
paths on DOS and a Linux, macOS or Windows build for OTS attachment. Keep other
writers out of the DOS destination directory while UC2 is running.

The automated checks cover both layout choices and ties, exact selected bytes
and statistics, versions, duplicates, empty files, poisoned-writer allocation
failures, late payload corruption, write/close/publication failures, temporary
name collisions, non-ASCII paths and no-overwrite races. The Windows test also
holds a destination open to force failed replacement and checks restoration
of its read-only attribute. Linux fault injection is kept in the test harness,
with no production fault controls.

GitHub hosts release downloads and PyPI hosts Python distributions. SDF mirrors
source, release tags and git-bug records. Neither a new release nor these changes
imply acceptance of the pending libarchive, MC or TC proposals.
