## Executed checks

The 35 Python tests pass on each of 20 installed wheels: CPython 3.10-3.14 on
Linux x86-64, Windows x86-64, macOS Intel, and macOS Apple Silicon. They cover
Huffman and rANS, existing reference archives, versions, literal semicolon
names, Unicode archive paths, corrupt inputs, resource limits, unsafe extraction
paths, callback errors, garbage collection, and preservation of existing output.
Binary CLI tests include every byte value, CR/LF, and Ctrl-Z.

CI builds the source distribution, builds a wheel from that source, installs
it, and passes the same 35 tests. Twine's strict metadata check passes for the
source archive and all wheels. The 21 files published on PyPI match the tested
artifacts' SHA-256 hashes.

A fresh virtual environment installed `uc2==3.0.0a4` directly from PyPI and
passed all 35 tests. The installed `uc2` entry point reports `3.0.0a4`. All 27
published GitHub assets match the local release files' SHA-256 hashes.

A separate Linux ASan/UBSan build passes all 35 tests. AddressSanitizer runs
with leak detection disabled for the Python process; this is not a leak-audit
claim. Core CI also passes native Linux/macOS/MSVC tests, a DJGPP cross-build,
libarchive and actual bsdtar tests, the WCX DLL ABI test on Windows, regression
replay, and 90-second decoder and round-trip fuzzing sessions. Native Total
Commander UI and 32-bit WCX validation remain pending.

Each standalone CLI is extracted from a tested wheel, smoke-tested on its
target OS, and packaged with licenses and a binary hash. Release verification
compares that binary with its source wheel. The release supplies corresponding
source, `BUILD-INFO.json`, and `SHA256SUMS`.

## Review coverage and repairs

The release-scoped task-qa/task-at attempt used a frozen snapshot and requested
independent reviews from Claude, Gemini, and Grok. Gemini returned a substantive
review. Claude subscription access failed, Grok reached its ten-minute timeout
without a response, and API fallbacks were unavailable. Only one external
review completed; unavailable reviewers are not counted as clean reviews.

Gemini's findings led to these repairs:

- Negative C-wrapper limits now fail instead of wrapping into large unsigned
  values. The test also covers mutation of public Python limit attributes.
- Invalid name components and file/directory path collisions fail during
  metadata indexing.
- Output exceeding a declared size raises `BadArchiveError` consistently.
- Python-enabled CMake builds retain the normal CLI installation rules.
- Documentation states POSIX extraction permissions precisely and clarifies
  the read-only API and the two Python-version requirements for tests.

The suggested GC use-after-free was not substantiated: an executing bound C
method holds a strong reference to its receiver, so the reader cannot be an
unreachable cycle during its callback. A regression test collects during
source callbacks and confirms that a later unreachable reader/source cycle is
reclaimed. No speculative GC guard was added.

Additional CI findings were repaired before publication: a Python 3.10 macro
could not be used in a preprocessor expression; Windows binary pipes used text
mode; the libarchive download paired an xz hash with a gzip URL; and the DOS
signature check rejected version text from the current `file` utility.

README prose scans found no em/en dashes, spaced double-hyphen clauses, curly
quotes, stock formulaic phrases, or assistant-process leakage. CLI flags and
ordinary Markdown structure were retained. Prose edits were rescanned after
repair; this is a scoped scan, not a completed whole-project task-at audit.
The final scan covered 927 words in `README.md` and 578 in `python/README.md`,
with one post-edit rescan.

## Remaining limits

The project-wide audit is still open in git-bug `c9edf0b`. The unused standalone
BLAKE3 module still fails official vectors and must not support integrity
claims. The reader uses legacy archive checksums. Turbo/method 80 and
multi-volume archives are unsupported; archive offsets are 32-bit. Python
creation remains a CLI operation. Extraction limits are documented in the
[Python API guide](../../python/README.md).
