# Project audit, 13-14 November 2026

This audit addresses the project-wide QA/prose task (`c9edf0b`) and the review
of [libarchive PR #3832](https://github.com/libarchive/libarchive/pull/3832).
The baseline was `18da0843955da9ee04294c44b382df7dc318862d`. Implementation
commits are `95c1fbc`, `2f5f31d`, `bc6f904` and `b1fa52a`. The requested
task-qa, task-at and task-elegance reviews are complete for the scope below.
These are source changes after alpha11, not a new package release.

## Review scope and method

The audit covers the owned native library, CLI and platform shims, Python
interfaces and snapshot/preservation tools, integrations, browser application,
build/packaging code and maintained documentation. Original third-party source,
licence text and dated release/benchmark records retain their historical meaning.
It is not a new independent audit of vendored cryptographic implementations or
libarchive's unrelated formats.

Independent seats used Kimi K3, GPT-6 Astra and Grok 4.7 Build/Build Fast. Kimi
replaced Claude according to the existing project preference. Gemini subscription
authentication failed on the available hosts, and the same-model API fallback
had no credit; Astra filled that seat. Empty, truncated and timed-out reviews
are recorded as incomplete, including an early Kimi length stop and several
Grok attempts. They are not approvals. Implementation assistants are not counted
as independent reviewers.

Each reviewer received complete files in a frozen bundle with SHA-256 hashes,
the applicable contracts, and instructions to review independently. Initial
reviews covered each area in full. Later rounds checked repairs with their
callers and tests. Each repair bundle supplied complete files, with its scope
and omissions recorded in the reviewer receipts. Unchanged modules were not
reviewed again in every round. Review verdicts are static assessments, separate
from the executed tests below.

## Confirmed repairs

| Area | Change and verification |
| --- | --- |
| libarchive input | Optional proposal uses seek/read callbacks, rejects pipes before entries, and accepts regular-file stdin. The full adapter retains bounded pipe spooling. Short-read callbacks and real bsdtar exercise both contracts. |
| Decoder errors | Structural and I/O failures propagate; excess Huffman output fails even with a valid prefix checksum. Historical EOF lookahead remains supported. Raw/chunk framing stays strict. |
| Directory parsing | Empty and overflowing repeated long-name tags fall back safely to DOS names. Turbo directory sizing uses the counting writer, including the allocation-retry path. |
| Allocation and storage | rANS allocation errors remain sticky; frequency correction preserves all present symbols. Merkle failure clears partial state. Blockstore range, type, read, write and close failures propagate. Fault injection covers failures and retries. |
| Helper bounds | Dictionary and OTS lengths use checked arithmetic; BCJ uses defined unsigned arithmetic; BWT has bounded allocations and no global comparator state. |
| Compression output | The byte counter rejects output beyond `UINT_MAX` before invoking the sink and preserves its count when the sink fails. Boundary tests avoid allocating a multi-GiB buffer. |
| Legacy ingest | Hash zero no longer aliases hash one. Chunk counts are checked before opening the destination. Version-one lengths and negative reads fail safely. |
| CLI extraction | Balanced directory traversal, safe selection-list lifetime, order-independent recursive selection, unsafe-name/type rejection, missing-parent errors and read-only directory handling have regressions. |
| Windows I/O | UTF-8 file operations, wide offsets/timestamps, enumeration errors and read-only replacement are checked. Reserved device names and aliases fail before filesystem creation. |
| CLI output | OTS suffix reads are bounded; malformed URI lengths and final/earlier stdio failures fail explicitly. Option pre-parsing preserves short-option operands and stops at `--`. Shared staged-stream ownership closes files before error cleanup or publication on all creation/ingest paths. |
| Tar metadata | The first explicit directory header updates an implicit parent even after children. A validated writer setter preserves identity, order and limits. USTAR, GNU, PAX and V7 order cases pass. |
| Python snapshots | Reparse points, directory chunk references and invalid orphan sizes are rejected before publication. Restore staging is cleaned even if reservation cleanup fails. |
| Documentation | Corrected volume support, compatibility and interface scope, partial format details, provenance, commands and package links. The reply distinguishes the two adapters and makes no wider-demand or acceptance claim. |

## Elegance decisions

The Total Commander metadata path now grows its owning array geometrically and
reuses sorted pointer indexes for directory lookup, versions and collision
checks. Entry order and newest-version numbering are unchanged. A portable
benchmark of the actual metadata code reduced 10,064-entry opening from 2.62 s
to 0.11 s. The 50,064-entry case completed in 0.96 s; the baseline exceeded
120 s. These are portable-host timings, not native Windows timings. Native
Windows ABI tests validate behaviour separately.

The writer's conflict checks now use an index of parent IDs and encoded names,
with full comparisons for hash collisions. The entry array remains the owner
and retains archive order. Insertion of 10,000 empty files fell from 2.295 s to
0.020 s; 50,000 fell from 95.71 s to 0.151 s. The indexed 100,000-entry case took
0.289 s. A mixed 4,206-entry archive is byte-for-byte identical before and after.
These measurements cover insertion, not complete archive creation. Growth,
collisions, versions and allocation failures have separate regression tests.

Merkle hashing now consumes little-endian fields incrementally, preserving
pinned roots while avoiding temporary hash buffers. BWT comparison state belongs
to each operation. Tar metadata correction changes the existing directory record
without buffering or rewriting the input stream.

Several proposals remain follow-ups with explicit reasons:

- The decoded-entry temporary file preserves validation before libarchive
  returns bytes and bridges the synchronous decoder to a pull interface. Removing
  it requires a resumable decoder design.
- CLI parent/version indexing is still quadratic, and ordinary ingest retains a
  separate container-framing path. Changing these needs representative scale and
  compatibility measurements; the WCX improvement does not establish CLI scale.
- CLI extraction and OTS attachment can leave partial changes on an output
  failure. Documentation now states this; transactional publication is separate
  work. Python extraction already stages output.
- Preservation migration accepts ordinary single-container UC2 input. Simply
  reopening a multipart set by path would lose complete source-hash provenance.
- Legacy ingest hash verification and the LZ4 helper's 256 KiB stack table are
  recorded follow-ups. Neither is presented as a repaired archive-path feature.
- Suggested rewrites of old release records were declined: their statements are
  dated evidence. Current guides carry current capabilities. SHA-256 integrity
  checks do not authenticate an archive's author.

## Executed checks

- All 35 native CTests passed at `b1fa52a`, including original DOS application
  round trips, the decoder/writer/tar repairs, CLI option handling and staged
  output cleanup.
- The final installed Python package passed 239 tests; two native Windows
  junction cases were skipped on Linux. Each Windows CPython 3.10-3.14 wheel
  job passed 227 tests, including those junction cases; 14 POSIX cases were skipped.
- Clang ASan/UBSan covered the native suite and repaired boundaries. CLI I/O
  tests disable their address-space cap under ASan because its shadow mapping
  requires a larger virtual address space.
- Four libFuzzer harnesses completed bounded ASan/UBSan runs without findings;
  CI repeats regression replay and fuzzing.
- Historical migration verified all pinned hashes and sizes for 39 archives and
  684 entries through both ZIP and tar, including after the strict-output fix.
- Two 2 GiB decoded entries, Huffman and rANS, restored into a counting and
  byte-checking sink under 41 MiB peak RSS. This does not validate a multi-GiB
  snapshot repository or crash recovery.
- The current-master libarchive suite ran 969 tests with zero failures and
  83 skips. Focused enabled CMake and Autotools runs passed 130,717 assertions
  each; the disabled Debug build passed 5,626 with warnings as errors.
- Full and optional bsdtar tests cover listing, skip/select, stdin/pipe policy,
  resource limits and a 128 MiB restore under a 96 MiB address-space limit.
- Strict Sphinx rendering, man-page rendering, assertion-side-effect lint and
  whitespace checks pass. Prose scans were followed by contextual review; real
  flags, technical notation and author names were preserved.

All four workflows pass for the final source `b1fa52a`:
[Build](https://github.com/evvaletov/uc2/actions/runs/43547917100),
[Distributions](https://github.com/evvaletov/uc2/actions/runs/43547917149),
[Docs and browsers](https://github.com/evvaletov/uc2/actions/runs/43547917083),
and [Integration releases](https://github.com/evvaletov/uc2/actions/runs/43547917204).
These include Windows/macOS/Linux native tests, DOS, WCX, the optional reader,
wheel tests, browser engines and bounded fuzzing. They build artifacts without
publishing a new alpha release.

The initial CI run exposed a GNU-only test invocation with `--` after the
archive operand. Moving the delimiter before the archive tests the intended
literal-filename behaviour on all supported getopt implementations. Its first
failure remains part of the record.

A GCC 14 Release build of libarchive with UC2 disabled and warnings as errors
stopped on diagnostics in the unchanged RAR/RAR5 readers. The Debug build with
the same warning policy passed. No unrelated source patch or warning suppression
was applied.

The optional libarchive configuration is tested on Linux. Native Windows/macOS
UC2 and WCX checks do not establish that optional upstream configuration on those
platforms. Upstream acceptance, dependency policy and format-ID allocation remain
external decisions.
