Thanks for the review. UC2 is an archive format: it stores paths, metadata and
file versions, with compressed payloads that can share dictionaries. The case
for this reader is access to surviving DOS-era collections through existing
libarchive tools.

1. I built and checked unuc2 0.8. Its `-p` option writes decoded files to stdout;
   it does not accept an archive pipe. `unuc2 -l -` treats `-` as a filename,
   and piping an archive to `unuc2 -l /dev/stdin` fails at `fseek` on Linux.
   A command-line fallback would therefore still need seekable input, plus a
   way to transfer entry names and metadata back to libarchive. It cannot use
   the gzip filter arrangement directly.

2. I have revised the adapter to use libarchive's seek/read callbacks for input
   and removed the input spool from this proposal. UC2 locates its compressed
   directory through an absolute offset, then the decoder seeks back to the
   files and shared dictionaries described there. Pipes and non-seekable
   filters now fail before exposing entries, with a message to save the archive
   to a file first. Seekable stdin remains supported.

   There is still one decoded-entry temporary file. libuc2 has a synchronous
   push decoder, while libarchive requests data blocks; this bridge also lets
   the adapter check the entry before returning bytes. That file is subject to
   the decoded-output limits and is released between entries. Listing and
   skipping do not decode payloads. Removing this remaining spool would need
   a resumable decoder interface; the current revision does not provide one.

3. The original structures and implementation are preserved in
   [SUPERMAN.H](https://github.com/evvaletov/uc2/blob/main/original/UC2_source/src/SUPERMAN.H)
   and the surrounding source. There is also a
   [partial format guide](https://github.com/evvaletov/uc2/blob/main/docs/format.rst),
   [Bobrowski's portable reader](https://torinak.com/~jb/unuc2/), and
   [Klaus Post's Go implementation](https://github.com/klauspost/uc2).

The preservation case is concrete but small: the recorded compatibility corpus
contains 13 historical collections, alongside independent and original-encoder
fixtures. I do not have usage figures establishing wider demand. Keeping the
dependency optional and the adapter limited to historical formats reduces the
scope, but does not remove the maintenance burden you raised. The integration
can remain external if that trade-off does not fit libarchive.
